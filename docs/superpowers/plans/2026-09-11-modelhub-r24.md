# ModelHub R24 Implementation Plan

> Execute in the isolated `feat/modelhub-r24` worktree. Use test-driven-development, dispatching-parallel-agents for disjoint installer work, and verification-before-completion.

**Goal:** Deliver a local arm64 R24 installer package and a PR against the fork main without installing or publishing a release.

**Architecture:** Preserve the fork's ModelHub native Responses pipeline and custom history bucket. Select stable upstream fixes by capability, then make routed switching transactional and gate system managed routing behind an explicit per-provider opt-in. Installer LaunchAgent replacement is an independent checked state machine.

**Tech Stack:** Rust/Tauri, React/TypeScript, Bash, SQLite, Vitest.

**Spec:** User-approved R24-001 through R24-004 recorded in the task; the implementation constraints below are the execution snapshot.

## Global constraints

- Default mobile remote sessions to false. Do not create or write `/etc/codex/managed_config.toml` unless opted in; opt-out only undoes CC Switch-owned route keys after a previous opt-in.
- ModelHub uses `custom`; Official disables only Codex takeover and does not stop other applications' proxy.
- Preserve official auth, user configuration and unified history. Tests must use isolated homes/config paths. Never print credentials or real launchd environments.
- Build a local package only. No installation into Applications, real launchd mutation, release upload or merge of the PR.
- R24-003 candidates are selected by compatibility; document selected and deferred commits.

## Verification cases

- R23 template selects `custom` and defines `[model_providers.custom]`; selected proxy URL matches current listening configuration.
- Remote metadata missing/false causes no managed-file writes. Read-only legacy conflict detection is allowed: do not report Official direct routing while R23 forced system routing still conflicts. On-to-off restores only owned keys and preserves unrelated settings.
- ModelHub/Official repeated switches converge even with stale takeover flags or stopped listener. Failures restore live config, backups, current IDs and managed route; incomplete rollback is returned to UI.
- Installer job already loaded, delayed bootout, nonzero-but-absent bootout, real bootout failure, bootstrap failure, helper failure, rollback failure and repeated install are modeled independently.
- UI rereads all route state after success/failure and blocks conflicting actions while switching.
- Original source checkout remains on main; generated assets remain ignored; no secrets in commits or public package.
